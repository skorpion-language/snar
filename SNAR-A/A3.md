# SNAR-A3

## Skorpion Norms And Rules — Generation A — Standard A3

### Syntax of the Skorpion Programming Language

---

## 1. Scope

**1.1.** This standard defines the **syntactic grammar** of the Skorpion programming language.

**1.2.** The subject of this standard is: which sequences of tokens (as defined in **SNAR-A2**) form syntactically valid Skorpion source text, and which do not; and the structural shape of every construct that appears in a syntactically valid source text.

**1.3.** This standard does **not** define:

- a) the vocabulary of the language — see **SNAR-A2**;
- b) what any construct means or evaluates to — see **SNAR-A4**;
- c) type rules, name resolution, or any other property that is not visible from the shape of the token sequence;
- d) any implementation detail.

**1.4.** In case of any conflict between this standard and other documents of the SNAR-A generation regarding syntax, this standard takes precedence.

---

## 2. Conformance

**2.1.** A source text is **syntactically valid** if and only if it can be derived from the `Program` production defined in §4.

**2.2.** A source text that cannot be derived from the `Program` production is **syntactically invalid**.

**2.3.** The set of syntactically valid source texts is determined solely by this standard.

---

## 3. Grammar Notation

**3.1.** A grammar rule has the form

```
Nonterminal ::= Production
```

**3.2.** The grammar operators are:

- `A B` — concatenation (A followed by B);
- `A | B` — alternation;
- `A?` — zero or one occurrence of A;
- `A*` — zero or more occurrences of A;
- `A+` — one or more occurrences of A;
- `( ... )` — grouping;
- `"literal"` — a token whose lexeme is exactly `literal`;
- `? description ?` — a terminal described informally.

**3.3.** Token names (e.g. `Identifier`, `VersionLiteral`) refer to the token types defined in **SNAR-A2**.

**3.4.** Where the prose rules of this standard and the grammar of §14 disagree, the prose rules take precedence.

---

## 4. Program

**4.1.**

```
Program       ::= Import* GlobalConst* ErrorDecl* TopLevel*
GlobalConst   ::= "const" Type ExportMarker? Identifier "=" Expr
TopLevel      ::= Function | IncludeC
```

**4.2.** The order `Import* GlobalConst* ErrorDecl* TopLevel*` is fixed:

- a) no `Import` may appear after a `GlobalConst`, an `ErrorDecl`, a `Function`, or an `IncludeC`;
- b) no `GlobalConst` may appear after an `ErrorDecl`, a `Function`, or an `IncludeC`;
- c) no `ErrorDecl` may appear after a `Function` or an `IncludeC`.

**4.3.** A `Program` with zero `Import`, zero `GlobalConst`, zero `ErrorDecl`, and zero `TopLevel` is syntactically valid.

**4.4.** A `GlobalConst` introduces a top-level constant. Its identifier becomes visible to all subsequent top-level constructs and to all function bodies in the program. `GlobalConst` is distinguished from an `ErrorDecl` by the token immediately following `const`:

- if the next token is a type name (`int`, `string`, `float`, `double`, `bool`, `char`, `arr`, `dict`, `any`, `T`, or `void`), the construct is a `GlobalConst`;
- otherwise, the construct is an `ErrorDecl`.

**4.5.** The `ExportMarker` (`*`), if present, appears between the `Type` and the `Identifier` of a `GlobalConst`. A `GlobalConst` without the export marker is **exported** and is visible to importers of the enclosing module or library. A `GlobalConst` with the export marker is **private** to its module or library and is not visible to importers.

---

## 5. Imports

**5.1.**

```
Import     ::= "use" ImportAll? ImportPath Alias?
ImportAll  ::= "#"
Alias      ::= "&" Identifier
```

**5.2.**

```
ImportPath  ::= LibraryPath | ModulePath
LibraryPath ::= "lib" ":" Identifier "/" LibraryName Version?
LibraryName ::= Identifier ("-" Identifier)*
Version     ::= VersionLiteral
ModulePath  ::= Identifier ("/" Identifier)*
```

**5.3.** A `VersionLiteral` is a token of type `VERSION` (SNAR-A2 §8.8).

**5.4.** The `#` token, if present, appears immediately after `use` and before `ImportPath`; it marks an import-all.

**5.5.** The `Alias` (an `&` token followed by an `Identifier`) appears after `ImportPath`.

**5.6.** Examples:

```
use std/os
use std/io
use #lib:iamtowvee/MyLib
use #lib:iamtowvee/MyLib@1.0.0
use std/strings &str
use lib:alice/my-lib
```

---

## 6. Types

### 6.1. General Form

**6.1.1.**

```
Type ::= "void"
       | "int" | "string" | "float" | "double" | "bool" | "char" | "dict" | "any"
       | "arr"
       | "arr" "[" ArrayElemType "]"
       | "T" "<" Type ("," Type)+ ">"
```

### 6.2. Array Element Types

**6.2.1.**

```
ArrayElemType ::= "int" | "string" | "float" | "double" | "bool" | "char" | "any"
                | "arr"
                | "arr" "[" ArrayElemType "]"
```

**6.2.2.** The token sequence `arr` without brackets is equivalent to `arr[any]`.

**6.2.3.** An `arr` element type may be nested to any finite depth.

**6.2.4.** The element type `void`, `dict`, and any union type `T<...>` is **not** syntactically permitted inside `arr[...]`.

### 6.3. Union Types

**6.3.1.** A union type `T<...>` shall contain at least one component type.

**6.3.2.** A union type shall **not** contain another union type as a component.

**6.3.3.** The token sequence `T<X>` with a single component is equivalent to `X`.

**6.3.4.** Examples of syntactically valid types:

```
void
int
arr
arr[int]
arr[arr[int]]
T<int>
T<int, string>
T<int, arr[float], char>
```

---

## 7. Error Declarations

**7.1.**

```
ErrorDecl    ::= "const" ErrorName "{" ErrorFields? "}" "=" NewMarker? ErrorParent
ErrorFields  ::= ErrorField ("," ErrorField)*
ErrorField   ::= Identifier ":" Type DefaultValue?
DefaultValue ::= "[" Expr "]"
NewMarker    ::= "new"
ErrorParent  ::= Identifier | "Error"
```

**7.2.** The `ErrorName` identifier shall begin with an uppercase letter (`A`–`Z`).

**7.3.** An `ErrorDecl` may appear at the top level of a `Program` (per §4) or as a `Statement` inside a `Block` (per §10.1).

**7.4.** Example:

```
const HttpError{
    code: int,
    message: string,
    retryable: bool [false]
} = new Error
```

---

## 8. Functions

**8.1.**

```
Function      ::= AsyncMarker? Type PrivateMarker? Identifier "(" Params? ")" Block
AsyncMarker   ::= "async"
PrivateMarker ::= "*"
Params        ::= Param ("," Param)*
Param         ::= VariadicParam | TypedParam
VariadicParam ::= "..." Identifier
TypedParam    ::= Type Identifier DefaultArg?
DefaultArg    ::= "=" Expr
```

**8.2.** The `async` marker, if present, precedes the return `Type`.

**8.3.** The `*` token, if present, appears between the return `Type` and the function name `Identifier`. The `*` marks the function as **not exported** (private to the enclosing module or library).

**8.4.** A `Function` that has an `async` marker **SHALL NOT** have `void` as its return type.

**8.5.** A `VariadicParam` shall be the final `Param`. A `VariadicParam` followed by `,` is invalid.

**8.6.** The function body shall be a `Block` (§9).

**8.7.** Examples of syntactically valid parameter lists:

```
()
(int a)
(int a, int b)
(string name, int age)
(int a, ...rest)
(arr[int] xs)
(dict d)
```

---

## 9. Blocks

**9.1.**

```
Block ::= "{" Statement* "}"
```

**9.2.** A `Block` may be empty.

---

## 10. Statements

**10.1.**

```
Statement ::= BreakStmt
            | ContinueStmt
            | DoWhileStmt
            | IfStmt
            | WhileStmt
            | IknowIdoStmt
            | ForStmt
            | ReturnStmt
            | CaseStmt
            | TryStmt
            | ThrowStmt
            | PromiseStmt
            | AwaitStmt
            | ConstStmt
            | VarDeclStmt
            | IncludeC
            | AssignmentOrCall
            | ExpressionStmt
            | ErrorDecl
```

**10.2.** The `;` token may follow any `Statement` inside a `Block`.

**10.3.** Break and continue:

```
BreakStmt    ::= "break"
ContinueStmt ::= "continue"
```

**10.4.** Variable declaration:

```
VarDeclStmt ::= Type Identifier ("=" Expr)?
```

`void` shall **not** appear as the `Type` of a `VarDeclStmt`.

**10.5.** Constant declaration:

```
ConstStmt ::= "const" Type Identifier "=" Expr
```

The initializer `Expr` is mandatory. The `*` export marker is **not** permitted on a `ConstStmt`: private constants are a top-level construct only (see §4.1).

**10.6.** Conditional:

```
IfStmt ::= "if" "(" Expr ")" Block
           ("elsif" "(" Expr ")" Block)*
           ("else" Block)?
```

Both parentheses around each `Expr` are mandatory.

**10.7.** While loop:

```
WhileStmt ::= "while" "(" Expr ")" Block
```

**10.8.** Do–while loop:

```
DoWhileStmt ::= "do" Block "while" "(" Expr ")"
```

**10.9.** For-in loop:

```
ForStmt ::= "for" "(" Type Identifier "in" Expr ")" Block
```

The element `Type` and the `in` keyword are both mandatory.

**10.10.** Case statement:

```
CaseStmt    ::= "case" "(" Expr ")" "{" CaseBranch* CaseDefault? "}"
CaseBranch  ::= CasePattern Block ","
CaseDefault ::= CaseDefaultMarker Block ","
CaseDefaultMarker ::= Identifier    /* the identifier whose lexeme is "_" */
CasePattern ::= Expr
              | "(" Expr ("," Expr)+ ")"
```

- a) a `CaseStmt` shall contain at least one `CaseBranch` or one `CaseDefault`;
- b) a `,` token shall follow every `CaseBranch` and every `CaseDefault`;
- c) a `CaseDefault` shall appear only after all `CaseBranch`es.

The `_` marker in `CaseDefaultMarker` is a regular identifier token whose lexeme is exactly `_`; it is not a reserved keyword.

**10.11.** Return:

```
ReturnStmt ::= "return" Expr?
```

**10.12.** Throw:

```
ThrowStmt ::= "throw" Expr
```

The `Expr` is mandatory.

**10.13.** Try:

```
TryStmt       ::= "try" Block CatchClause+
CatchClause   ::= "catch" CatchHeader? Block
CatchHeader   ::= "(" CatchTypeName ("as" Identifier)? ")"
CatchTypeName ::= Identifier ("." Identifier)* | "Error"
```

A `TryStmt` shall contain at least one `CatchClause`.

**10.14.** Promise:

```
PromiseStmt ::= "Promise" "[" Expr "]"
```

**10.15.** Await:

```
AwaitStmt ::= "await" UnaryExpr
```

**10.16.** `IknowIdo`:

```
IknowIdoStmt ::= "IknowIdo" Block
```

**10.17.** `includeC`:

```
IncludeC ::= "includeC" TildeBlock
```

`TildeBlock` is the token of SNAR-A2 §8.9.

**10.18.** Assignment or call:

```
AssignmentOrCall ::= Identifier ";"
                   | Identifier PostfixOp
                   | Identifier (FieldAccess | ArrayIndex)? AssignOp Expr
                   | Identifier CallSuffix

FieldAccess ::= "." Identifier
ArrayIndex  ::= "[" Expr "]"
CallSuffix  ::= "(" Arguments? ")"
              | "." Identifier "(" Arguments? ")"
PostfixOp   ::= "++" | "--"
AssignOp    ::= "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "**="
```

A bare `Identifier` followed by neither a postfix operation, nor an assignment operator, nor a call suffix, nor `;` is **invalid** as a statement.

**10.19.** Expression statement:

```
ExpressionStmt ::= Expr
```

An `ExpressionStmt` shall begin with one of the following tokens: `STRING`, `NUMBER`, `(`.

**10.20.** Error declaration as statement: an `ErrorDecl` (§7) may appear as a `Statement`.

---

## 11. Expressions

**11.1.**

```
Expr ::= TernaryExpr | RangeCallExpr | BinaryExpr
```

**11.2.** Primary expressions:

```
Primary ::= NumberLiteral
          | StringLiteral
          | CharLiteral
          | UnicodeLiteral
          | "null" | "true" | "false"
          | Identifier
          | PostfixExpr
          | ErrorInstance
          | CallExpr
          | TypeOfExpr
          | PromiseExpr
          | AwaitExpr
          | ParenExpr
          | ArrayLiteral
          | DictLiteral
```

**11.3.** Unary expressions:

```
UnaryExpr ::= ("$" | "!" | "-") UnaryExpr
            | Primary Postfix* FormatSuffix?
```

**11.4.** Binary expressions:

```
BinaryExpr ::= UnaryExpr (BinaryOp UnaryExpr)*
BinaryOp   ::= "+" | "-" | "*" | "/" | "%" | "**"
             | "<" | ">" | "<=" | ">=" | "==" | "!=" | "="
             | "&&" | "||"
```

**11.5.** Range:

```
RangeExpr ::= UnaryExpr ".." UnaryExpr
```

**11.6.** Range call:

```
RangeCallExpr ::= RangeExpr "." Identifier "(" Arguments? ")"
```

**11.7.** Ternary:

```
TernaryExpr ::= Expr "?" Expr ":" Expr
```

**11.8.** Calls:

```
CallExpr  ::= Identifier "(" Arguments? ")"
            | Identifier "." Identifier "(" Arguments? ")"
Arguments ::= Expr ("," Expr)*
```

**11.9.** Postfix operations:

```
Postfix ::= "[" Expr "]"
          | "." "length"
          | "." Identifier
          | "." Identifier "(" Arguments? ")"
```

**11.10.** Postfix increment / decrement expression:

```
PostfixExpr ::= Identifier PostfixOp
PostfixOp   ::= "++" | "--"
```

`PostfixExpr` is a valid `Primary` (see §11.2). In this position it denotes an expression whose value is obtained from the variable after applying the operation; whether and how the variable is modified is a matter of semantics (SNAR-A4).

**11.11.** Format suffix:

```
FormatSuffix    ::= "^" FixedPrecision
                  | "^" TrimSpec
FixedPrecision  ::= DecimalDigits "f"
                  | DecimalDigits "F"
TrimSpec        ::= "X" DecimalDigits
                  | "X" "{" DecimalDigits ("," DecimalDigits)* "}"
DecimalDigits   ::= /[0-9]+/
```

**11.12.** In `FixedPrecision`, the decimal digits shall form a non-negative integer not exceeding 20.

**11.13.** In `TrimSpec`, every sequence of decimal digits shall be non-empty.

**11.14.** Error instance:

```
ErrorInstance ::= Identifier "{" (ErrField ("," ErrField)*)? "}"
ErrField      ::= Identifier ":" Expr
```

A field identifier shall **not** appear more than once in the same `ErrorInstance`.

**11.15.** TypeOf:

```
TypeOfExpr ::= "type" "(" Expr ")"
```

**11.16.** Promise expression:

```
PromiseExpr ::= "Promise" "[" Expr "]"
```

**11.17.** Await expression:

```
AwaitExpr ::= "await" UnaryExpr
```

**11.18.** Parenthesized expression:

```
ParenExpr ::= "(" Expr ")"
```

**11.19.** Array literal:

```
ArrayLiteral ::= "[" (Expr ("," Expr)*)? "]"
               | "(" Expr ("," Expr)+ ")"
```

**11.20.** Dict literal:

```
DictLiteral ::= "{" (DictEntry ("," DictEntry)*)? "}"
DictEntry   ::= Identifier ":" Expr
```

A key identifier shall **not** appear more than once in the same `DictLiteral`.

## 12. Operator Precedence

**12.1.** Precedence, from highest to lowest:

| Level | Operators | Associativity |
|-------|-----------|---------------|
| 6 | `..` | left |
| 5 | `**` | right |
| 4 | `*` `/` `%` | left |
| 3 | `+` `-` | left |
| 2 | `<` `>` `=` `!=` `==` `<=` `>=` | left |
| 1 | `&&` | left |
| 0 | `\|\|` | left |
| — | `?:` | right |
| — | unary `$` `!` `-` | right |
| — | postfix `.` `[]` `()` `++` `--` | left |

**12.2.** The `?:` operator has lower precedence than all binary operators.

**12.3.** Unary operators bind more tightly than any binary operator and than `?:`.

**12.4.** Postfix operators bind most tightly and are left-associative.

**12.5.** `**` is right-associative; all other binary operators are left-associative.

**12.6.** The `=` punctuator, when it appears at binary-expression level (e.g. in a chained-assignment expression such as `a = b = c`), has the same precedence as the comparison operators and is left-associative. The `=` punctuator at statement level (in `AssignmentOrCall`, §10.18) introduces an assignment and is not part of a binary expression.

**12.7.** Example:

```
1 + 2 * 3 ** 2 - 4 .. 10
```

is grouped as

```
((1 + (2 * (3 ** 2))) - (4 .. 10))
```

## 13. Syntactically Invalid Forms

The following token sequences are syntactically invalid (that is, they cannot be derived from the `Program` production):

**13.1.** An `Import` after a `GlobalConst`, an `ErrorDecl`, a `Function`, or an `IncludeC`.

**13.2.** A `GlobalConst` after an `ErrorDecl`, a `Function`, or an `IncludeC`.

**13.3.** An `ErrorDecl` after a `Function` or an `IncludeC`.

**13.4.** A `Function` without a return `Type`.

**13.5.** A `Function` without a function name `Identifier`.

**13.6.** A `Function` with an `async` marker and return type `void`.

**13.7.** A `VariadicParam` not in the final position of a `Params` list.

**13.8.** A `Type` containing `T<...>` nested inside `T<...>`.

**13.9.** A `Type` containing `T<...>` with zero component types.

**13.10.** An `arr[...]` whose element type is `void`, `dict`, or a union type.

**13.11.** An `ErrorName` that does not begin with an uppercase letter.

**13.12.** A `VarDeclStmt` whose `Type` is `void`.

**13.13.** A `ConstStmt` without an initializer `Expr`.

**13.14.** A `ConstStmt` bearing the `*` export marker.

**13.15.** A `GlobalConst` without an initializer `Expr`.

**13.16.** A `CaseStmt` with zero `CaseBranch`es and no `CaseDefault`.

**13.17.** A `CaseBranch` or `CaseDefault` not followed by `,`.

**13.18.** A `CaseDefault` appearing before a `CaseBranch`.

**13.19.** A `TryStmt` with zero `CatchClause`s.

**13.20.** A `ThrowStmt` without an expression.

**13.21.** An `ErrorInstance` with a field name appearing more than once.

**13.22.** A `DictLiteral` with a key name appearing more than once.

**13.23.** A `FormatSuffix` whose fixed precision exceeds 20.

**13.24.** A `FormatSuffix` whose decimal digit sequence is empty.

**13.25.** An `ExpressionStmt` that does not begin with `STRING`, `NUMBER`, or `(`.

**13.26.** A bare `Identifier` as a statement without a following `;`, postfix operation, assignment, or call suffix.

**13.27.** A `PostfixExpr` used in a statement position where a full `AssignmentOrCall` is expected (the statement form is `Identifier PostfixOp`, not a general `PostfixExpr`).

**13.28.** Any unterminated construct (an unclosed `Block`, parenthesized group, bracket group, or brace group).

## 14. Grammar Summary

**14.1.** The complete syntactic grammar of the Skorpion language:

```
Program      ::= Import* GlobalConst* ErrorDecl* TopLevel*
TopLevel     ::= Function | IncludeC

GlobalConst  ::= "const" Type ExportMarker? Identifier "=" Expr

Import       ::= "use" ImportAll? ImportPath Alias?
ImportAll    ::= "#"
Alias        ::= "&" Identifier
ImportPath   ::= LibraryPath | ModulePath
LibraryPath  ::= "lib" ":" Identifier "/" LibraryName Version?
LibraryName  ::= Identifier ("-" Identifier)*
Version      ::= VersionLiteral
ModulePath   ::= Identifier ("/" Identifier)*

ErrorDecl    ::= "const" ErrorName "{" ErrorFields? "}" "=" NewMarker? ErrorParent
ErrorFields  ::= ErrorField ("," ErrorField)*
ErrorField   ::= Identifier ":" Type DefaultValue?
DefaultValue ::= "[" Expr "]"
NewMarker    ::= "new"
ErrorParent  ::= Identifier | "Error"
ErrorName    ::= Identifier

Function      ::= AsyncMarker? Type PrivateMarker? Identifier "(" Params? ")" Block
AsyncMarker   ::= "async"
PrivateMarker ::= "*"
Params        ::= Param ("," Param)*
Param         ::= VariadicParam | TypedParam
VariadicParam ::= "..." Identifier
TypedParam    ::= Type Identifier DefaultArg?
DefaultArg    ::= "=" Expr

Type          ::= "void"
                | "int" | "string" | "float" | "double" | "bool" | "char" | "dict" | "any"
                | "arr"
                | "arr" "[" ArrayElemType "]"
                | "T" "<" Type ("," Type)+ ">"

ArrayElemType ::= "int" | "string" | "float" | "double" | "bool" | "char" | "any"
                | "arr"
                | "arr" "[" ArrayElemType "]"

Block         ::= "{" Statement* "}"

Statement     ::= BreakStmt | ContinueStmt | DoWhileStmt | IfStmt | WhileStmt
                | IknowIdoStmt | ForStmt | ReturnStmt | CaseStmt | TryStmt
                | ThrowStmt | PromiseStmt | AwaitStmt | ConstStmt
                | VarDeclStmt | IncludeC | AssignmentOrCall
                | ExpressionStmt | ErrorDecl

BreakStmt     ::= "break"
ContinueStmt  ::= "continue"
VarDeclStmt   ::= Type Identifier ("=" Expr)?
ConstStmt     ::= "const" Type Identifier "=" Expr
IfStmt        ::= "if" "(" Expr ")" Block ("elsif" "(" Expr ")" Block)* ("else" Block)?
WhileStmt     ::= "while" "(" Expr ")" Block
DoWhileStmt   ::= "do" Block "while" "(" Expr ")"
ForStmt       ::= "for" "(" Type Identifier "in" Expr ")" Block
CaseStmt      ::= "case" "(" Expr ")" "{" CaseBranch* CaseDefault? "}"
CaseBranch    ::= CasePattern Block ","
CaseDefault   ::= CaseDefaultMarker Block ","
CaseDefaultMarker ::= Identifier    /* lexeme "_" */
CasePattern   ::= Expr | "(" Expr ("," Expr)+ ")"
ReturnStmt    ::= "return" Expr?
ThrowStmt     ::= "throw" Expr
TryStmt       ::= "try" Block CatchClause+
CatchClause   ::= "catch" CatchHeader? Block
CatchHeader   ::= "(" CatchTypeName ("as" Identifier)? ")"
CatchTypeName ::= Identifier ("." Identifier)* | "Error"
PromiseStmt   ::= "Promise" "[" Expr "]"
AwaitStmt     ::= "await" UnaryExpr
IknowIdoStmt  ::= "IknowIdo" Block
IncludeC      ::= "includeC" TildeBlock

AssignmentOrCall ::= Identifier ";"
                   | Identifier PostfixOp
                   | Identifier (FieldAccess | ArrayIndex)? AssignOp Expr
                   | Identifier CallSuffix
FieldAccess  ::= "." Identifier
ArrayIndex   ::= "[" Expr "]"
CallSuffix   ::= "(" Arguments? ")"
               | "." Identifier "(" Arguments? ")"
PostfixOp    ::= "++" | "--"
AssignOp     ::= "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "**="

ExpressionStmt ::= Expr

Expr          ::= TernaryExpr | RangeCallExpr | BinaryExpr
TernaryExpr   ::= Expr "?" Expr ":" Expr
RangeCallExpr ::= RangeExpr "." Identifier "(" Arguments? ")"
RangeExpr     ::= UnaryExpr ".." UnaryExpr
BinaryExpr    ::= UnaryExpr (BinaryOp UnaryExpr)*
BinaryOp      ::= "+" | "-" | "*" | "/" | "%" | "**"
                | "<" | ">" | "<=" | ">=" | "==" | "!=" | "="
                | "&&" | "||"

UnaryExpr     ::= ("$" | "!" | "-") UnaryExpr
                | Primary Postfix* FormatSuffix?

Primary       ::= NumberLiteral | StringLiteral | CharLiteral | UnicodeLiteral
                | "null" | "true" | "false"
                | Identifier
                | PostfixExpr
                | ErrorInstance | CallExpr | TypeOfExpr
                | PromiseExpr | AwaitExpr | ParenExpr
                | ArrayLiteral | DictLiteral

PostfixExpr   ::= Identifier PostfixOp

CallExpr      ::= Identifier "(" Arguments? ")"
                | Identifier "." Identifier "(" Arguments? ")"
Arguments     ::= Expr ("," Expr)*

Postfix       ::= "[" Expr "]"
                | "." "length"
                | "." Identifier
                | "." Identifier "(" Arguments? ")"

FormatSuffix   ::= "^" FixedPrecision | "^" TrimSpec
FixedPrecision ::= DecimalDigits "f" | DecimalDigits "F"
TrimSpec       ::= "X" DecimalDigits
                 | "X" "{" DecimalDigits ("," DecimalDigits)* "}"
DecimalDigits  ::= /[0-9]+/

ErrorInstance  ::= Identifier "{" (ErrField ("," ErrField)*)? "}"
ErrField       ::= Identifier ":" Expr

TypeOfExpr    ::= "type" "(" Expr ")"
PromiseExpr   ::= "Promise" "[" Expr "]"
AwaitExpr     ::= "await" UnaryExpr
ParenExpr     ::= "(" Expr ")"
ArrayLiteral  ::= "[" (Expr ("," Expr)*)? "]"
                | "(" Expr ("," Expr)+ ")"
DictLiteral   ::= "{" (DictEntry ("," DictEntry)*)? "}"
DictEntry     ::= Identifier ":" Expr
```

**14.2.** The grammar of §14.1 is informative. Where it disagrees with the prose rules of §4–§13, the prose rules take precedence.

## Appendix A — Examples of Syntactically Valid Programs

### A.1. Minimal program

```
void main() {
}
```

### A.2. Imports, global constants, and top-level constructs

```
use #lib:iamtowvee/MyLib
use std/os
use std/io
use std/strings &str

const int MAX = 100
const string GREETING = "hello"
const arr[int] PRIMES = [2, 3, 5, 7]
const int *HIDDEN = 42

const HttpError{
    code: int,
    message: string,
    retryable: bool [false]
} = new Error

void main(arr args) {
    io.sendln(GREETING)
}
```

### A.3. Functions with parameters

```
void foo(int a, ...some) {
    for (any f in some) {
        println(f)
    }
}

async dict fetch() {
    return {age: 25}
}
```

### A.4. Statements

```
void main() {
    const int MAX = 100
    int i = 0
    i += 1
    i -= 2
    i *= 3
    i /= 2
    i %= 2
    i **= 2

    if (MAX == 100) {
        println(MAX)
    } elsif (MAX > 100) {
        println("big")
    } else {
        println("small")
    }

    while (i < 10) {
        i++
    }

    do {
        i--
    } while (i > 0)

    for (int n in [1, 2, 3]) {
        println(n)
    }

    case (i) {
        (1, 2, 3) { println("few") },
        (4, 5, 6) { println("medium") },
        _ { println("many") },
    }

    try {
        throw HttpError{code: 404, message: "not found"}
    } catch (HttpError as e) {
        println(e.message)
    } catch {
        println("unknown")
    }
}
```

### A.5. Expressions, including postfix `++` / `--` as expressions

```
void main() {
    int a = 1 + 2 * 3 ** 2 - 4 .. 10
    int b = (a > 0) ? a : -a
    string s = "hello"
    string t = $a
    string u = s ^X{1,8}
    float f = 3.14159 ^2f
    arr[int] xs = [1, 2, 3]
    dict d = {name: "Skorpion", age: 25}

    int c = a++          // PostfixExpr as expression
    int e = a--          // PostfixExpr as expression
}
```

### A.6. Error declarations inside a function body

### A.7. Empty program

A source text consisting of zero tokens is syntactically valid (it derives from `Program` with all repetitions taking zero occurrences).
