# SNAR-A3

## Skorpion Norms And Rules, A generation. Standard A3

This standard defines the **syntax** of the Skorpion programming language with the `*.sk` extension. It describes **which token sequences** are accepted by the parser and **which AST node** the parser produces for each accepted sequence.

**Scope.** SNAR-A3 defines only **syntax**:
- which tokens are expected;
- in which order;
- which errors are reported when the order is violated;
- which AST node is built.

**Out of scope.** SNAR-A3 does **not** define:
- types of expressions (SNAR-A4);
- scope and visibility (SNAR-A4);
- runtime behaviour (SNAR-A4);
- error codes beyond the ones already emitted by the reference parser (informative).

**Reference implementation.** All token names and AST node names in this standard match `front/lexer.go` and `front/ast.go`. §14 lists every known divergence.

## 0. Common Rules

### R-C1. Rule of Token Stream

The input to the parser is the token stream produced by the lexer according to SNAR-A2.

The parser reads tokens one at a time. At any point, the parser has:
- `current` — the token just consumed;
- `peek` — the next token (lookahead of 1).

The parser is **LL(1)** in the sense that every decision is made from `peek.Type` and, when needed, `peek.Literal`.

### R-C2. Rule of EOF

The parser stops at `TOKEN_EOF`.

### R-C3. Rule of Token Consumption

A rule **consumes** tokens from the stream. Consumed tokens are never re-read.

A rule **looks ahead** at `peek` without consuming it.

### R-C4. Rule of Optional Semicolon

A Semicolon (`TOKEN_SEMICOLON`) may optionally follow a statement.

A Semicolon is **never required** by this standard.

A Semicolon after a **block** (e.g., after `if (...) { ... }`) is permitted and ignored.

### R-C5. Rule of Case Sensitivity

All keywords, identifiers, and operators are **case-sensitive** (SNAR-A2, R-C5).

### R-C6. Rule of Mandatory Parentheses in Control Flow

All control-flow conditions (`if`, `elsif`, `while`, `do-while`, `case`) and the header of `for-in` **must** be enclosed in `TOKEN_LPAREN` … `TOKEN_RPAREN`.

### R-C7. Rule of Uniqueness

Duplicate top-level function signatures and duplicate error-type names are rejected. See §5 and §4.

### R-C8. Rule of Block Structure

A **block** is `TOKEN_LBRACE` { statement } `TOKEN_RBRACE`.

A block may contain zero statements.

### R-C9. Rule of Error Reporting

Each rule below lists the **error codes** that the reference parser emits. The codes are **informative**; the exact numbers may change. The **conditions** are normative.

### R-C10. Rule of AST Node

Each rule lists the **AST node type** that the parser produces. AST node names match `front/ast.go`. A parser that builds a different AST is conformant as long as it preserves the same information.

### R-C11. Rule of Conformance

See §11.

## 1. Program Structure

### 1.1. Rule of Program Layout

A `*.sk` file has the following layout:

| Section | Tokens | Order |
|---------|--------|-------|
| Imports | zero or more `import` | first |
| Top-level error declarations | zero or more `error-decl` | second |
| Top-level declarations | zero or more `function` or `includeC` | third |

An `import` after an `error-decl` or a `function` is **invalid**.

An `error-decl` after a `function` is **invalid**.

Functions and `includeC` blocks may be interleaved.

### 1.2. Rule of Parsing Strategy

The parser uses the following strategy:

```
advance()                                   // skip first token
if HasFatal() return empty Program

while peek is TOKEN_KEYWORD("use"):
    parseImport()                           // → []*Import
    if HasFatal() return Program

while peek is TOKEN_KEYWORD("const"):
    parseErrorDecl()                        // → []*ErrorDecl
    if HasFatal() return Program

while peek is not TOKEN_EOF:
    if peek is TOKEN_INCLUDE_C:
        parseIncludeC()                     // → GlobalIncludeC []string
    else if peek is a type keyword or TOKEN_KEYWORD("async"):
        parseFunction()                     // → []*Function
    else:
        advance()                           // skip garbage (see §14.1)
```

#### 1.2.1. Rule of Type Keyword Detection

A token is a **type keyword** for the purpose of top-level dispatch if its literal is one of:

```
void  int  string  float  double  bool  char  arr  dict  any  T
```

This is exactly the `isType()` predicate in `parser.go`.

#### 1.2.2. Rule of `async` Detection

The keyword `async` always begins a function declaration. `async` is not a type; it is a **prefix** to the return type.

### 1.3. Rule of the Program Node

The parser produces:

```go
&Program{
    Position:        Position{Line, Column},
    Imports:         []*Import,
    Functions:       []*Function,
    ErrorDecls:      []*ErrorDecl,
    GlobalIncludeC:  []string,
}
```

`Position` is the position of the first token in the file.

## 2. Types

### 2.1. Rule of Type Parsing

`parseType()` returns a **string** that encodes the type. The string is consumed by later rules (var-decl, param, etc.).

| Input | Returned string |
|-------|-----------------|
| `void` | `"void"` |
| `int` | `"int"` |
| `string` | `"string"` |
| `float` | `"float"` |
| `double` | `"double"` |
| `bool` | `"bool"` |
| `char` | `"char"` |
| `dict` | `"dict"` |
| `any` | `"any"` |
| `arr` | `"arr[any]"` |
| `arr[<type>]` | `"arr[<type>]"` |
| `arr[arr[<type>]]` | `"arr[arr[<type>]]"` |
| `T<A>` | `"A"` (normalized) |
| `T<A,B>` | `"T<A,B>"` |

### 2.2. Rule of Simple Type Parsing

**Tokens consumed:** one token.

**Condition:** `peek.Type == TOKEN_KEYWORD` and `peek.Literal` is one of the simple type names (§2.1).

**AST:** the returned string is the literal.

**Errors:** none.

### 2.3. Rule of Array Type Parsing

**Tokens consumed:**
1. `TOKEN_KEYWORD("arr")` — always the first token.
2. Optional: `TOKEN_LBRACKET("]")`, inner type (recursive `parseType`), `TOKEN_RBRACKET("]")`.

**Subcases:**

| Tokens | Result |
|--------|--------|
| `arr` | `"arr[any]"` |
| `arr` `[` `int` `]` | `"arr[int]"` |
| `arr` `[` `arr` `[` `string` `]` `]` | `"arr[arr[string]]"` |
| `arr` `[` | **error 0561** (unknown element type) |

#### 2.3.1. Rule of Empty Array Brackets

`arr[]` is **invalid**: `TOKEN_RBRACKET` immediately after `TOKEN_LBRACKET` is rejected with `0561`.

`arr[void]` is **invalid**: `0560`.

`arr[<not-a-type>]` is **invalid**: `0561`.

#### 2.3.2. Rule of Missing Closing Bracket

`arr[int` (no `]`) is **invalid**: `0514`.

### 2.4. Rule of Union Type Parsing

**Tokens consumed:**
1. `TOKEN_KEYWORD("T")`.
2. `TOKEN_LT("<")`.
3. One or more types (recursive `parseType`), separated by `TOKEN_COMMA(",")`.
4. `TOKEN_GT(">")`.

**Subcases:**

| Tokens | Result |
|--------|--------|
| `T` `<` `int` `>` | `"int"` (single-member normalization) |
| `T` `<` `int` `,` `string` `>` | `"T<int,string>"` |
| `T` `<` | **error 0608** (expected `<` — actually `0608` is for `T` without `<`) |
| `T` (no `<`) | **error 0608** |
| `T` `<` `T` `<` `int` `,` `string` `>` `,` `float` `>` | **error 0611** (nested union) |

#### 2.4.1. Rule of `T` Without `<`

`T` alone is **invalid**: `0608: Expected '<' after 'T'`.

#### 2.4.2. Rule of Nested Union

`T<T<...>, ...>` is **invalid**: `0611: Cannot nest T<...> inside T<...>`.

`T<int, arr[T<int, string>]>` is **valid**: the inner `T<...>` is inside an `arr[...]`, not directly a union member.

#### 2.4.3. Rule of Missing `>`

`T<int` (no `>`) is **invalid**: `0609`.

### 2.5. Rule of Invalid Types

Any token sequence that does not match §2.2–§2.4 is **invalid**. Examples:

| Source | Error |
|--------|-------|
| `dict[int]` | `0561` (no `[` after `dict`) |
| `int<string>` | `0561` |
| `arr.` | `0514` (expected `]`) |

## 3. Imports

### 3.1. Rule of Import Syntax

**Tokens consumed:**
1. `TOKEN_KEYWORD("use")`.
2. Optional: `TOKEN_HASH("#")` → sets `Import.All = true`.
3. Import path (see §3.2, §3.3).
4. Optional: `TOKEN_AMPERSAND("&")`, `TOKEN_IDENT` → sets `Import.Alias`.
5. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&Import{
    Position: Position{Line, Column},
    Path:     string,
    Alias:    string,
    All:      bool,
    IsLib:    bool,
}
```

#### 3.1.1. Rule of `#` Marker

The `#` marker is syntactically accepted and sets `Import.All = true`.

**Current semantics:** none (see §14.10). `All` is stored but never read.

#### 3.1.2. Rule of `&` Alias

The `&` marker followed by an identifier sets `Import.Alias = "..."`.

**Current semantics:** none (see §14.11). `Alias` is stored but never read.

#### 3.1.3. Rule of All Four Combinations

| Source | `All` | `Alias` |
|--------|-------|---------|
| `use path` | `false` | `""` |
| `use path &Alias` | `false` | `"Alias"` |
| `use #path` | `true` | `""` |
| `use #path &Alias` | `true` | `"Alias"` |

### 3.2. Rule of Module Path

**Tokens consumed:**

1. `TOKEN_IDENT`.
2. Zero or more (`TOKEN_SLASH`, `TOKEN_IDENT`).

**AST:** the path is concatenated with `/` into `Import.Path`.

**Example:** `use std/strings` → `Import.Path = "std/strings"`.

### 3.3. Rule of Library Path

**Detection:** the first token after optional `#` is `TOKEN_IDENT` with literal `"lib"`.

**Tokens consumed:**
1. `TOKEN_IDENT("lib")`.
2. `TOKEN_COLON(":")` — **must** be present, error `0553` otherwise.
3. `TOKEN_IDENT` (author).
4. `TOKEN_SLASH("/")`.
5. `TOKEN_IDENT` (name).
6. Zero or more (`TOKEN_MINUS("-")`, `TOKEN_IDENT`) — hyphens in name.
7. Optional: `TOKEN_VERSION("@x.y.z")`.

**AST:** `Import.Path = "lib:<author>/<name>"` or `"lib:<author>/<name>@<version>"`.

**Example:** `use lib:alice/math@1.0.0` → `Import.Path = "lib:alice/math@1.0.0"`, `Import.IsLib = true`.

## 4. Error Declarations

### 4.1. Rule of Top-Level Error Declaration

**Tokens consumed:**
1. `TOKEN_KEYWORD("const")`.
2. `TOKEN_IDENT` — **must** begin with `A`–`Z`, error `0581` otherwise.
3. `TOKEN_LBRACE("{"")`.
4. Zero or more error fields.
5. `TOKEN_RBRACE("}")`.
6. `TOKEN_EQUALS("=")`.
7. Optional: `TOKEN_KEYWORD("new")` — sets `ErrorDecl.IsNew = true`.
8. `TOKEN_IDENT` or `TOKEN_KEYWORD("Error")` — the parent.

**AST:**

```go
&ErrorDecl{
    Position: Position{Line, Column},
    Name:     string,
    Fields:   []*ErrorField,
    Parent:   string,
    IsNew:    bool,
}
```

### 4.2. Rule of Error Field

**Tokens consumed:**
1. `TOKEN_IDENT` (field name).
2. `TOKEN_COLON(":")`.
3. `TOKEN_KEYWORD` — must be a type keyword (§1.2.1). Error `0585` otherwise.
4. Optional: `TOKEN_LBRACKET("[")`, expression, `TOKEN_RBRACKET("]")` — default value.

**AST:**

```go
&ErrorField{
    Position:     Position{Line, Column},
    Name:         string,
    Type:         string,
    DefaultValue: Node,   // nil if absent
}
```

**Errors:**
- `0583` if the field name is not `TOKEN_IDENT`.
- `0584` if `:` is missing.
- `0585` if the type is not a type keyword.
- `0586` if the default value is not closed by `]`.

### 4.3. Rule of Parent

**Tokens consumed:**
1. `TOKEN_KEYWORD("Error")` — the root type; **or**
2. `TOKEN_IDENT` — a previously declared error type.

**Errors:** `0589` if neither token is found.

**Semantic check** (SNAR-A4): the parent must be declared or be `Error`.

### 4.4. Rule of Local Error Declaration

Inside a function body, `const` is dispatched as follows (see §8.22):

| Next token after `const` | Construct |
|--------------------------|-----------|
| A type keyword | **Constant variable** (`const-var-decl`, §8.3) |
| `TOKEN_IDENT` (not a type keyword) | **Local error declaration** (§4.1) |
| `TOKEN_KEYWORD("Error")` | Not allowed as a declaration name |

## 5. Functions

### 5.1. Rule of Function Syntax

**Tokens consumed:**
1. Optional: `TOKEN_KEYWORD("async")` — sets `Function.IsAsync = true`.
2. `parseType()` — the return type. Error `0500` if the next token is not a type keyword.
3. Optional: `TOKEN_STAR("*")` — sets `Function.IsExport = false`.
4. `TOKEN_IDENT` — the function name. Error `0501` if absent.
5. `TOKEN_LPAREN("(")`. Error `0507` if absent.
6. Optional parameter list (§5.2).
7. `TOKEN_RPAREN(")")`. Error `0508` if absent.
8. `parseBlock()`.

**AST:**

```go
&Function{
    Position:    Position{Line, Column},
    NamePos:     Position{Line, Column},
    Name:        string,
    ReturnType:  string,
    Params:      []*Param,
    Body:        *Block,
    IsExport:    bool,
    IsAsync:     bool,
    File:        string,
}
```

**Errors:**
- `0500` — expected return type.
- `0501` — expected function name.
- `0507` — expected `(`.
- `0508` — expected `)`.
- `0509` — expected `{` for the body.
- `0665` — `async void` is forbidden.

### 5.2. Rule of Async Functions

**Detection:** `peek.Type == TOKEN_KEYWORD && peek.Literal == "async"`.

**Tokens consumed:**
1. `TOKEN_KEYWORD("async")`.
2. The rest of §5.1.

**Rules:**
- `async` is only valid as a prefix to a function.
- The return type **must not** be `void`. `async void f()` → error `0665`.
- `IsAsync = true` in the AST.

**Errors:** `0665`.

#### 5.2.1. Rule of Where `async` Is Accepted

`async` is accepted at **top level** only, as a function prefix. It is **not** accepted:
- as a statement;
- as an expression;
- as a type.

`async` followed by something that is not a function is **invalid** (`0500`).

### 5.3. Rule of Parameters

**Tokens consumed:** a comma-separated list, or empty.

```
param-list = [ param , { "," , param } ] ;
```

**AST:** each param becomes `*Param`.

#### 5.3.1. Rule of Typed Parameter

**Tokens consumed:**
1. `parseType()` — the type.
2. `TOKEN_IDENT` — the name.
3. Optional: `TOKEN_EQUALS("=")`, expression — the default.

**AST:**

```go
&Param{
    Position:     Position{Line, Column},
    Name:         string,
    Type:         string,
    DefaultValue: Node,   // nil if absent
    IsVariadic:   false,
}
```

**Errors:**
- `0502` — expected parameter type.
- `0503` — expected parameter name.

#### 5.3.2. Rule of Variadic Parameter

**Tokens consumed:**
1. `TOKEN_ELLIPSIS("...")`.
2. `TOKEN_IDENT` — the name.

**AST:**

```go
&Param{
    Position:   Position{Line, Column},
    Name:       string,
    Type:       "arr[any]",
    IsVariadic: true,
}
```

**Rules:**
- The variadic parameter has **no type** and **no default value**.
- A variadic parameter **must** be the last parameter. `...a, int b` → error `0503`.

**Errors:** `0503`.

### 5.4. Rule of Function Body

The body is a **block** (§6). It may be empty: `{ }`.

### 5.5. Rule of `async` and Return Type

| Source | Result |
|--------|--------|
| `int foo() { }` | OK, `IsAsync = false` |
| `async int foo() { }` | OK, `IsAsync = true` |
| `async void foo() { }` | **error 0665** |
| `void foo() { }` | OK, `IsAsync = false` |

## 6. Blocks

### 6.1. Rule of Block Syntax

**Tokens consumed:**
1. `TOKEN_LBRACE("{")`. Error `0542` if absent.
2. Zero or more statements (§8), each followed by an optional `TOKEN_SEMICOLON`.
3. `TOKEN_RBRACE("}")`. Error `0543` if absent.
4. If `TOKEN_EOF` is reached before `}`, error `0523`.

**AST:**

```go
&Block{
    Position:   Position{Line, Column},
    Statements: []Node,
}
```

### 6.2. Rule of Empty Block

`{ }` is valid and produces `Statements = []`.

### 6.3. Rule of Statement Termination

After each statement, if `peek.Type == TOKEN_SEMICOLON`, the semicolon is consumed and ignored.

## 7. Expressions

### 7.1. Rule of Expression Categories

Every expression belongs to exactly one of:

| Category | Section |
|----------|---------|
| Primary | §7.2 |
| Postfix | §7.3 |
| Unary | §7.4 |
| Binary | §7.5 |
| Range | §7.6 |
| Ternary | §7.7 |
| Call | §7.8 |
| Range-Method | §7.9 |

Precedence is defined in §9.

### 7.2. Rule of Primary Expressions

A **primary expression** is one of:

| Category | Token(s) | AST |
|----------|----------|-----|
| Number literal | `TOKEN_NUMBER` | `*Number{Value}` |
| Unicode literal | `TOKEN_UNICODE_LIT` | `*UnicodeLiteral{Codepoint}` |
| String literal | `TOKEN_STRING` | `*String{Value}` |
| Char literal | `TOKEN_CHARLIT` | `*CharLiteral{Value}` |
| `null` | `TOKEN_KEYWORD("null")` | `*NullLiteral` |
| `true`, `false` | `TOKEN_KEYWORD` | `*Ident{Name}` |
| Identifier | `TOKEN_IDENT` | see §7.2.1 |
| Error instance | `TOKEN_IDENT` or `TOKEN_KEYWORD("Error")`, then `{` | `*ErrorInstance` |
| Dictionary literal | `TOKEN_LBRACE` | `*DictLiteral` |
| Array literal `[...]` | `TOKEN_LBRACKET` | `*ArrayLiteral` |
| Parenthesized / array `(...)` | `TOKEN_LPAREN` | §7.2.7 |
| `Promise[expr]` | `TOKEN_KEYWORD("Promise")` | `*PromiseSet` |
| `type(expr)` | `TOKEN_KEYWORD("type")` | `*TypeOf` |
| `await expr` | `TOKEN_KEYWORD("await")` | `*AwaitExpr` |

#### 7.2.1. Rule of Identifier Primary

After `TOKEN_IDENT`, the parser inspects `peek`:

| Next token | Produces |
|------------|----------|
| `TOKEN_PLUSPLUS` / `TOKEN_MINUSMINUS` | `*PostfixExpr` |
| `TOKEN_LBRACE` | `*ErrorInstance` (via §7.2.2) |
| `TOKEN_LPAREN` | `*CallExpr` (via §7.8) |
| Anything else | `*Ident{Name}` |

#### 7.2.2. Rule of Error Instance

**Tokens consumed:**
1. `TOKEN_IDENT` or `TOKEN_KEYWORD("Error")`.
2. `TOKEN_LBRACE("{")`.
3. Zero or more `field : expression`, separated by `TOKEN_COMMA(",")`.
4. `TOKEN_RBRACE("}")`.

**AST:**

```go
&ErrorInstance{
    Position: Position{Line, Column},
    TypeName: string,
    Fields:   map[string]Node,
}
```

**Errors:**
- `0591` — expected field name.
- `0592` — expected `:`.
- `0593` — expected `}`.
- `0594` — duplicate field.
- `0590` — expected `{` after `Error`.

#### 7.2.3. Rule of Dictionary Literal

**Tokens consumed:**
1. `TOKEN_LBRACE("{"")`.
2. Zero or more `identifier : expression`, separated by `TOKEN_COMMA(",")`.
3. `TOKEN_RBRACE("}")`.

**AST:**

```go
&DictLiteral{
    Position: Position{Line, Column},
    Elements: []*DictElement,   // {Position, Key, Value}
}
```

**Errors:**
- `0650` — expected key (not an identifier).
- `0651` — expected `:`.
- `0652` — expected `}`.

#### 7.2.4. Rule of Array Literal `[...]`

**Tokens consumed:**
1. `TOKEN_LBRACKET("[")`.
2. Zero or more expressions, separated by `TOKEN_COMMA(",")`.
3. `TOKEN_RBRACKET("]")`.

**AST:**

```go
&ArrayLiteral{
    Position: Position{Line, Column},
    Elements: []Node,
}
```

**Rules:**
- `[]` is valid.
- Trailing comma is **forbidden**.
- `[...]` may contain **any** expression.

**Errors:**
- `0515` — expected `]`.

#### 7.2.5. Rule of Parenthesized Expression / Array Literal `(...)`

**Tokens consumed:**
1. `TOKEN_LPAREN("(")`.
2. An expression.
3. If `peek.Type == TOKEN_COMMA`:
   - one or more additional expressions, separated by `TOKEN_COMMA`.
   - `TOKEN_RPAREN(")")`.
   - produce `*ArrayLiteral`.
4. Otherwise:
   - `TOKEN_RPAREN(")")`.
   - produce the inner expression **as-is** (parentheses are not preserved).

**Rules:**
- `(a)` → parenthesized expression, produces `*Ident` (the inner `a`).
- `(a, b)` → array literal with two elements.
- `()` → **invalid** (parser expects an expression, sees `)`).

**Errors:**
- `0541` — expected `)`.

#### 7.2.6. Rule of `Promise` Expression

**Tokens consumed:**
1. `TOKEN_KEYWORD("Promise")`.
2. `TOKEN_LBRACKET("[")`.
3. expression.
4. `TOKEN_RBRACKET("]")`.

**AST:**

```go
&PromiseSet{
    Position: Position{Line, Column},
    Value:    Node,
}
```

**Errors:**
- `0660` — expected `[` after `Promise`.
- `0661` — expected `]`.

#### 7.2.7. Rule of `type(...)` Expression

**Tokens consumed:**
1. `TOKEN_KEYWORD("type")`.
2. `TOKEN_LPAREN("(")`.
3. expression.
4. `TOKEN_RPAREN(")")`.

**AST:**

```go
&TypeOf{
    Position: Position{Line, Column},
    Expr:     Node,
}
```

**Errors:** `0540`, `0541`.

#### 7.2.8. Rule of `await` Expression

**Tokens consumed:**
1. `TOKEN_KEYWORD("await")`.
2. `parseUnary()` (§7.4).

**AST:**

```go
&AwaitExpr{
    Position: Position{Line, Column},
    Expr:     Node,
}
```

### 7.3. Rule of Postfix Expressions

After a primary expression, the parser loops over postfix operators until none match.

| Operator | Tokens | AST |
|----------|--------|-----|
| Index | `TOKEN_LBRACKET`, expr, `TOKEN_RBRACKET` | `*ArrayIndex` |
| Length | `TOKEN_DOT`, `TOKEN_IDENT("length")` | `*ArrayLength` |
| Field | `TOKEN_DOT`, `TOKEN_IDENT` (no `(`) | `*FieldAccess` |
| Method | `TOKEN_DOT`, `TOKEN_IDENT`, `TOKEN_LPAREN`, args, `TOKEN_RPAREN` | `*CallExpr` |
| Increment | `TOKEN_PLUSPLUS` | `*PostfixExpr` |
| Decrement | `TOKEN_MINUSMINUS` | `*PostfixExpr` |
| Format | `TOKEN_CARET`, format-spec | `*FormatExpr` |

#### 7.3.1. Rule of Indexing

**Receiver restriction:** only `*Ident`. `foo()[0]` → error `0516`.

**AST:**

```go
&ArrayIndex{
    Position: Position{Line, Column},
    Name:     string,   // the identifier
    Index:    Node,
}
```

**Errors:** `0516`.

#### 7.3.2. Rule of `.length`

**Receiver restriction:** only `*Ident`. `foo().length` → error `0520`.

**AST:**

```go
&ArrayLength{
    Position: Position{Line, Column},
    Name:     string,
}
```

**Errors:** `0520`.

#### 7.3.3. Rule of `.field`

**Receiver restriction:** only `*Ident`. `(a + b).field` → error `0520`.

**Detection:** `TOKEN_DOT` followed by `TOKEN_IDENT` followed by something that is **not** `TOKEN_LPAREN`.

**AST:**

```go
&FieldAccess{
    Position: Position{Line, Column},
    Object:   string,
    Field:    string,
}
```

**Errors:** `0520`.

#### 7.3.4. Rule of `.method(args)`

**Receiver restriction:** **any** expression. `a.b().c()` works via chained `ReceiverNode`.

**Tokens consumed:**
1. `TOKEN_DOT`.
2. `TOKEN_IDENT` (method name).
3. `TOKEN_LPAREN`.
4. Zero or more expressions, separated by `TOKEN_COMMA`.
5. `TOKEN_RPAREN`.

**AST:**

```go
&CallExpr{
    Position:     Position{Line, Column},   // position of the method name
    Name:         string,                    // method name
    Args:         []Node,
    Receiver:     string,                    // the receiver name if it is *Ident, else ""
    ReceiverNode: Node,                      // the full receiver expression
}
```

**Errors:**
- `0520` — expected field or method name.
- `0602` — expected `)`.

#### 7.3.5. Rule of `++` / `--`

**Tokens consumed:** `TOKEN_PLUSPLUS` or `TOKEN_MINUSMINUS`.

**AST:**

```go
&PostfixExpr{
    Position: Position{Line, Column},
    VarName:  string,
    Op:       "++" | "--",
}
```

#### 7.3.6. Rule of Format Suffix `^...`

**Tokens consumed:**
1. `TOKEN_CARET("^")`.
2. Either:
   - `TOKEN_NUMBER` ending in `f`/`F` → **precision form**;
   - `TOKEN_IDENT` starting with `X` → **trim form**.

##### 7.3.6.1. Precision Form `^Nf`

**Tokens:** `TOKEN_CARET`, `TOKEN_NUMBER` (`"3f"`, `"0f"`, …).

**Rules:**
- `N` must be 0–20.
- `N` must be an integer (no `.` allowed).

**AST:**

```go
&FormatExpr{
    Position: Position{Line, Column},
    Expr:     Node,   // the expression this suffix applies to
    Mode:     "Nf",
    N:        int,
}
```

**Errors:**
- `0620` — expected `f` after the precision.
- `0621` — invalid precision.
- `0622` — precision > 20.

##### 7.3.6.2. Trim Form `^X...`

**Tokens:** `TOKEN_CARET`, `TOKEN_IDENT("X...")`, optional `{ ... }`.

**Rules:**
- The `TOKEN_IDENT` must start with `X`.
- After `X`, either:
  - one or more digits: `^X9`, `^X18`;
  - `{`, one or more `TOKEN_NUMBER`, separated by `TOKEN_COMMA`, `}`: `^X{1,8}`, `^X{1, 2, 3}`.
- The trim set must be non-empty.

**AST:**

```go
&FormatExpr{
    Position: Position{Line, Column},
    Expr:     Node,
    Mode:     "X",
    TrimSet:  string,   // concatenated digits
}
```

**Errors:**
- `0623` — expected `}`.
- `0624` — empty trim set.
- `0625` — expected `Nf` or `X...`.

### 7.4. Rule of Unary Expressions

**Tokens consumed:**
1. Optional unary operator:
   - `TOKEN_NOT("!")`;
   - `TOKEN_MINUS("-")`;
   - `TOKEN_DOLLAR("$")`.
2. `parseUnary()` recursively.

**AST:**

```go
&UnaryExpr{
    Position: Position{Line, Column},
    Op:       "!" | "-" | "$",
    Expr:     Node,
}
```

**Rules:**
- Unary operators are **right-associative**: `!-x` → `!( -x )`.
- `await` is handled in `parsePrimary` (§7.2.8), not here.

### 7.5. Rule of Binary Expressions

**Tokens consumed:** the operator, then the right operand at the appropriate precedence (§9).

**AST:**

```go
&BinaryExpr{
    Position: Position{Line, Column},
    Left:     Node,
    Op:       string,
    Right:    Node,
}
```

Operators and precedence: §9.

### 7.6. Rule of Range Expressions

A range is a binary expression with the `TOKEN_DOTDOT("..")` operator. It is parsed by `parseBinary` and produces `*RangeExpr` instead of `*BinaryExpr`.

**AST:**

```go
&RangeExpr{
    Position: Position{Line, Column},
    Start:    Node,
    End:      Node,
}
```

### 7.7. Rule of Ternary Expressions

**Tokens consumed:**
1. `parseBinary(0)` — the condition.
2. `TOKEN_QUESTION("?")`.
3. expression — the then-branch.
4. `TOKEN_COLON(":")`.
5. expression — the else-branch.

**AST:**

```go
&TernaryExpr{
    Position:  Position{Line, Column},
    Condition: Node,
    Then:      Node,
    Else:      Node,
}
```

**Rules:**
- Right-associative: `a ? b : c ? d : e` → `a ? b : (c ? d : e)`.
- Lowest precedence (§9).

**Errors:** `0521` — expected `:`.

### 7.8. Rule of Call Expressions

**Two forms:**

| Form | Tokens |
|------|--------|
| Direct | `TOKEN_IDENT`, `TOKEN_LPAREN`, args, `TOKEN_RPAREN` |
| Module | `TOKEN_IDENT`, `TOKEN_DOT`, `TOKEN_IDENT`, `TOKEN_LPAREN`, args, `TOKEN_RPAREN` |

**AST (direct):**

```go
&CallExpr{
    Position: Position{Line, Column},
    Name:     string,
    Args:     []Node,
}
```

**AST (module):** same, with `Name = "module.func"`.

**Errors:**
- `0511` — expected function call after `.`.
- `0541` — expected `)`.

### 7.9. Rule of Range-Method Calls

**Detection:** after `parseBinary` produces a `*RangeExpr`, if `peek.Type == TOKEN_DOT`.

**Tokens consumed:**
1. `*RangeExpr` from `parseBinary`.
2. `TOKEN_DOT`.
3. `TOKEN_IDENT` — method name.
4. `TOKEN_LPAREN`.
5. Zero or more expressions, separated by `TOKEN_COMMA`.
6. `TOKEN_RPAREN`.

**AST:**

```go
&CallRangeExpr{
    Position: Position{Line, Column},
    Name:     string,
    Range:    *RangeExpr,
    Extra:    []Node,
}
```

**Rules:**
- Only valid when the range is followed by `.method(...)`.
- `1..4.length` is **invalid** (`0520`).

**Errors:** `0520`.

## 8. Statements

### 8.1. Rule of Statement Dispatch

The parser dispatches on `peek.Type` and, for `TOKEN_KEYWORD`, on `peek.Literal`:

| `peek.Type` | `peek.Literal` | Dispatch |
|-------------|----------------|----------|
| `TOKEN_KEYWORD` | `break` | §8.11 |
| `TOKEN_KEYWORD` | `continue` | §8.12 |
| `TOKEN_KEYWORD` | `do` | §8.9 |
| `TOKEN_KEYWORD` | `if` | §8.6 |
| `TOKEN_KEYWORD` | `while` | §8.8 |
| `TOKEN_KEYWORD` | `IknowIdo` | §8.19 |
| `TOKEN_KEYWORD` | `for` | §8.10 |
| `TOKEN_KEYWORD` | `return` | §8.13 |
| `TOKEN_KEYWORD` | `case` | §8.7 |
| `TOKEN_KEYWORD` | `try` | §8.14 |
| `TOKEN_KEYWORD` | `throw` | §8.15 |
| `TOKEN_KEYWORD` | `Promise` | §8.16 |
| `TOKEN_KEYWORD` | `await` | §8.17 |
| `TOKEN_KEYWORD` | `const` | §8.3 or §8.22 |
| `TOKEN_KEYWORD` | type keyword | §8.2 |
| `TOKEN_INCLUDE_C` | — | §8.18 |
| `TOKEN_IDENT` | — | §8.4 |
| `TOKEN_STRING`, `TOKEN_NUMBER`, `TOKEN_LPAREN` | — | §8.21 |
| `TOKEN_EOF` | — | end of block |
| anything else | — | error `0598` |

### 8.2. Rule of Variable Declaration

**Detection:** `peek.Type == TOKEN_KEYWORD` and `peek.Literal` is a type keyword (§1.2.1).

**Tokens consumed:**
1. `parseType()` — the type.
2. `TOKEN_IDENT` — the variable name.
3. Optional: `TOKEN_EQUALS("=")`, expression — the initializer.
4. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&VarDecl{
    Position: Position{Line, Column},
    Name:     string,
    Type:     string,
    ElemType: string,   // for arrays
    Expr:     Node,     // nil if absent
    IsArray:  bool,
    IsConst:  false,
}
```

**Errors:**
- `0504` — expected variable name.

**Rules:**
- `void x` parses but is rejected by SNAR-A4.
- `arr x` → `Type = "arr", ElemType = "any", IsArray = true`.

### 8.3. Rule of Constant Variable Declaration

**Detection:** `TOKEN_KEYWORD("const")` followed by a type keyword.

**Tokens consumed:**
1. `TOKEN_KEYWORD("const")`.
2. `parseType()` — the type.
3. `TOKEN_IDENT` — the variable name.
4. `TOKEN_EQUALS("=")`. Error `0557` if absent.
5. expression.
6. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&VarDecl{
    Position: Position{Line, Column},
    Name:     string,
    Type:     string,
    ElemType: string,
    Expr:     Node,
    IsArray:  bool,
    IsConst:  true,
}
```

**Errors:**
- `0557` — const requires initializer.
- `0504` — expected variable name.

### 8.4. Rule of Assignment

**Detection:** `TOKEN_IDENT`.

**Tokens consumed:**
1. `TOKEN_IDENT` — the target name.
2. One of the following:

| Next token | Consumed | AST |
|------------|----------|-----|
| `TOKEN_PLUSPLUS` / `TOKEN_MINUSMINUS` | op | `*PostfixExpr` |
| `TOKEN_DOT` | `.`, `TOKEN_IDENT`, then `TOKEN_LPAREN` → call, else **error** | `*CallExpr` or error |
| `TOKEN_LPAREN` | call | `*CallExpr` |
| `TOKEN_LBRACKET` | `[`, index, `]`, assign-op, expr | `*Assign` with `Index` |
| assign-op | op, expr | `*Assign` |
| `TOKEN_SEMICOLON` | `;` | `*Ident` |

#### 8.4.1. Rule of Simple Assignment

**Tokens consumed:**
1. `TOKEN_IDENT`.
2. assign-op (`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `**=`).
3. expression.

**AST:**

```go
&Assign{
    Position: Position{Line, Column},
    Name:     string,
    Expr:     Node,
    Op:       string,
}
```

#### 8.4.2. Rule of Index Assignment

**Tokens consumed:**
1. `TOKEN_IDENT`.
2. `TOKEN_LBRACKET("]")`.
3. expression — the index.
4. `TOKEN_RBRACKET("]")`.
5. assign-op. Error `0516` if absent.
6. expression.

**AST:**

```go
&Assign{
    Position: Position{Line, Column},
    Name:     string,
    Index:    Node,
    Expr:     Node,
    Op:       string,
}
```

**Errors:** `0516`.

#### 8.4.3. Rule of Field Assignment

**Field assignment** (`name.field = value`) is **not supported** by the reference parser (§14.3). The `TOKEN_DOT` branch requires `TOKEN_LPAREN` after the field name and reports `0511` otherwise.

`name.field` on the **right-hand side** of an assignment works via `parsePostfix`.

#### 8.4.4. Rule of Bare Identifier Statement

**Tokens consumed:**
1. `TOKEN_IDENT`.
2. `TOKEN_SEMICOLON`.

**AST:** `*Ident{Name}`.

**Rule:** `x` alone (without `;`) is a **syntax error**.

### 8.5. Rule of Postfix Increment/Decrement Statement

**Tokens consumed:**
1. `TOKEN_IDENT`.
2. `TOKEN_PLUSPLUS` or `TOKEN_MINUSMINUS`.

**AST:**

```go
&PostfixExpr{
    Position: Position{Line, Column},
    VarName:  string,
    Op:       "++" | "--",
}
```

### 8.6. Rule of Conditional Statement (`if`)

**Tokens consumed:**
1. `TOKEN_KEYWORD("if")`.
2. `TOKEN_LPAREN("(")`. Error `0540` if absent.
3. expression — the condition.
4. `TOKEN_RPAREN(")")`. Error `0541` if absent.
5. `parseBlock()` — the then-branch.
6. Zero or more:
   1. `TOKEN_KEYWORD("elsif")`.
   2. `TOKEN_LPAREN("(")`. Error `0540`.
   3. expression.
   4. `TOKEN_RPAREN(")")`. Error `0541`.
   5. `parseBlock()`.
7. Optional:
   1. `TOKEN_KEYWORD("else")`.
   2. `parseBlock()`.

**AST:**

```go
&IfStmt{
    Position:  Position{Line, Column},
    Condition: Node,
    Then:      *Block,
    Elsifs:    []*Elsif,   // each {Position, Condition, Then *Block}
    Else:      *Block,     // nil if absent
}
```

**Rules:**
- Parentheses are **mandatory** around `if` and `elsif` conditions.
- `if (x) { }` is valid; `if x { }` is **invalid** (`0540`).
- `else` has no condition and no parentheses.
- `elsif` may be repeated; `else` is optional.

**Errors:**
- `0540` — expected `(`.
- `0541` — expected `)`.
- `0542` — expected `{`.
- `0523` — unexpected EOF inside the block.

### 8.7. Rule of Case Statement

**Tokens consumed:**
1. `TOKEN_KEYWORD("case")`.
2. `TOKEN_LPAREN("(")`. Error `0540` if absent.
3. expression — the **scrutinee**.
4. `TOKEN_RPAREN(")")`. Error `0541` if absent.
5. `TOKEN_LBRACE("{")`. Error `0542` if absent.
6. Zero or more case branches (§8.7.1).
7. Optional default branch (§8.7.2).
8. `TOKEN_RBRACE("}")`. Error `0543` if absent.

**AST:**

```go
&CaseStmt{
    Position:  Position{Line, Column},
    Value:     Node,
    Branches:  []*CaseBranch,
    Default:   *Block,   // nil if absent
}
```

**Rules:**
- Parentheses around the scrutinee are **mandatory**.
- At least one branch (regular or default) is required. `0522` otherwise.
- Branches are tried in order.

**Errors:**
- `0540`, `0541`, `0542`, `0543`.
- `0522` — empty case.
- `0523` — unexpected EOF.

#### 8.7.1. Rule of Case Branch

**Tokens consumed:**
1. A pattern, which is one of:
   - **single pattern:** an expression;
   - **multi-pattern:** `TOKEN_LPAREN("(")`, expression, `TOKEN_COMMA(",")`, expression, …, `TOKEN_RPAREN(")")`.
2. `parseBlock()` — the body.
3. `TOKEN_COMMA(",")`. Error `0512` if absent.

**AST:**

```go
&CaseBranch{
    Position: Position{Line, Column},
    Patterns: []Node,
    Body:     *Block,
}
```

**Rules:**
- Single-pattern branch → `Patterns = [expr]`.
- Multi-pattern branch → `Patterns = [expr1, expr2, …]`.
- A trailing comma after the body is **mandatory**.

**Errors:**
- `0512` — expected `,` after a case branch.
- `0599` — expected `)` after multi-pattern.

#### 8.7.2. Rule of Default Branch

**Detection:** `peek.Type == TOKEN_IDENT && peek.Literal == "_"`.

**Tokens consumed:**
1. `TOKEN_IDENT("_")`.
2. `parseBlock()` — the body.
3. `TOKEN_COMMA(",")`. Error `0572` if absent.

**AST:** `Default: *Block`.

**Rules:**
- The default branch **must** be the last branch.
- The trailing comma is **mandatory**.
- `_` is the identifier `_`, not a special token.

**Errors:** `0572`.

#### 8.7.3. Rule of Branch Order

Branches are tested in source order. The default is tested last.

#### 8.7.4. Rule of Empty Case

`case (x) { }` is **invalid**: `0522: Empty case statement`.

### 8.8. Rule of While Loop

**Tokens consumed:**
1. `TOKEN_KEYWORD("while")`.
2. `TOKEN_LPAREN("(")`. Error `0540` if absent.
3. expression — the condition.
4. `TOKEN_RPAREN(")")`. Error `0541` if absent.
5. `parseBlock()`.

**AST:**

```go
&WhileStmt{
    Position:  Position{Line, Column},
    Condition: Node,
    Body:      *Block,
}
```

**Rules:**
- Parentheses around the condition are **mandatory**.

**Errors:** `0540`, `0541`.

### 8.9. Rule of Do-While Loop

**Tokens consumed:**
1. `TOKEN_KEYWORD("do")`.
2. `parseBlock()`. Error `0627` if `{` is missing.
3. `TOKEN_KEYWORD("while")`. Error `0627` if absent.
4. `TOKEN_LPAREN("(")`. Error `0540` if absent.
5. expression — the condition.
6. `TOKEN_RPAREN(")")`. Error `0627` if absent.
7. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&DoWhileStmt{
    Position:  Position{Line, Column},
    Body:      *Block,
    Condition: Node,
}
```

**Rules:**
- Parentheses around the condition are **mandatory**.
- The trailing semicolon is optional.

**Errors:**
- `0627` — expected `{`, `while`, or `)`.
- `0540` — expected `(`.

### 8.10. Rule of For-In Loop

**Tokens consumed:**
1. `TOKEN_KEYWORD("for")`.
2. `TOKEN_LPAREN("(")`. Error `0507` if absent.
3. `parseType()` — the element type. Error `0502` if absent.
4. `TOKEN_IDENT` — the element name. Error `0503` if absent.
5. `TOKEN_KEYWORD("in")`. Error `0630` if absent.
6. expression — the iterable.
7. `TOKEN_RPAREN(")")`. Error `0541` if absent.
8. `parseBlock()`.

**AST:**

```go
&ForInStmt{
    Position: Position{Line, Column},
    VarType:  string,
    VarName:  string,
    Iterable: Node,
    Body:     *Block,
}
```

**Rules:**
- Parentheses around the header are **mandatory**.
- The element type is required.
- `in` is required.

**Errors:** `0507`, `0502`, `0503`, `0630`, `0541`.

### 8.11. Rule of Break Statement

**Tokens consumed:**
1. `TOKEN_KEYWORD("break")`.
2. Optional: `TOKEN_SEMICOLON(";")`.

**AST:** `&BreakStmt{Position}`.

### 8.12. Rule of Continue Statement

**Tokens consumed:**
1. `TOKEN_KEYWORD("continue")`.
2. Optional: `TOKEN_SEMICOLON(";")`.

**AST:** `&ContinueStmt{Position}`.

### 8.13. Rule of Return Statement

**Tokens consumed:**
1. `TOKEN_KEYWORD("return")`.
2. If `peek` is not `TOKEN_RBRACE`, `TOKEN_SEMICOLON`, or `TOKEN_EOF`: expression.
3. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&ReturnStmt{
    Position: Position{Line, Column},
    Expr:     Node,   // nil for bare `return`
}
```

### 8.14. Rule of Try Statement

**Tokens consumed:**
1. `TOKEN_KEYWORD("try")`.
2. `parseBlock()`. Error `0574` if `{` is missing.
3. One or more catch clauses (§8.14.1). Error `0519` if none.

**AST:**

```go
&TryStmt{
    Position: Position{Line, Column},
    Body:     *Block,
    Catches:  []*CatchClause,
}
```

**Errors:**
- `0574` — expected `{`.
- `0519` — try requires at least one catch.

#### 8.14.1. Rule of Catch Clause

**Tokens consumed:**
1. `TOKEN_KEYWORD("catch")`.
2. Optional catch descriptor:
   1. `TOKEN_LPAREN("(")`.
   2. `TOKEN_IDENT` or `TOKEN_KEYWORD("Error")` — the error type name.
   3. Zero or more (`TOKEN_DOT`, `TOKEN_IDENT`) — qualified name.
   4. Optional: `TOKEN_KEYWORD("as")`, `TOKEN_IDENT` — the binding.
   5. `TOKEN_RPAREN(")")`. Error `0578` if absent.
3. `parseBlock()`. Error `0575` if `{` is missing.

**AST:**

```go
&CatchClause{
    Position: Position{Line, Column},
    TypeName: string,   // "" for catch-all
    VarName:  string,   // "" for no binding
    Body:     *Block,
}
```

**Three forms:**

| Form | `TypeName` | `VarName` |
|------|-----------|-----------|
| `catch { }` | `""` | `""` |
| `catch (MyError) { }` | `"MyError"` | `""` |
| `catch (MyError as e) { }` | `"MyError"` | `"e"` |

**Rules:**
- Parentheses are **optional** (§14.14).
- `as` binding is optional.
- Error type names may be qualified (`Module.Error`).

**Errors:**
- `0575` — expected `{`.
- `0576` — expected error type.
- `0577` — expected variable name after `as`.
- `0578` — expected `)`.

### 8.15. Rule of Throw Statement

**Tokens consumed:**
1. `TOKEN_KEYWORD("throw")`.
2. expression. Error `0579` if `peek` is `;`, `}`, or EOF.
3. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&ThrowStmt{
    Position: Position{Line, Column},
    Expr:     Node,
}
```

**Errors:** `0579`.

### 8.16. Rule of Promise-Set Statement

**Detection:** `peek.Type == TOKEN_KEYWORD && peek.Literal == "Promise"`.

**Tokens consumed:**
1. `TOKEN_KEYWORD("Promise")`.
2. `TOKEN_LBRACKET("[")`. Error `0660` if absent.
3. expression.
4. `TOKEN_RBRACKET("]")`. Error `0661` if absent.
5. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&PromiseSet{
    Position: Position{Line, Column},
    Value:    Node,
}
```

**Errors:** `0660`, `0661`.

### 8.17. Rule of Await Statement

**Detection:** `peek.Type == TOKEN_KEYWORD && peek.Literal == "await"`.

**Tokens consumed:**
1. `TOKEN_KEYWORD("await")`.
2. `parseUnary()`.
3. Optional: `TOKEN_SEMICOLON(";")`.

**AST:**

```go
&AwaitExpr{
    Position: Position{Line, Column},
    Expr:     Node,
}
```

### 8.18. Rule of `includeC` Block

**Tokens consumed:**
1. `TOKEN_INCLUDE_C("includeC")`.
2. `TOKEN_TILDE` — the tilde block. Error `0510` if absent.

**AST:**

```go
&IncludeC{
    Position: Position{Line, Column},
    Code:     string,   // the trimmed tilde block content
}
```

**Rules:**
- At top level, the code is appended to `Program.GlobalIncludeC`.
- Inside a function, the `*IncludeC` node is a statement.

**Errors:** `0510`.

### 8.19. Rule of `IknowIdo` Block

**Tokens consumed:**
1. `TOKEN_KEYWORD("IknowIdo")`.
2. `parseBlock()`. Error `0640` if `{` is missing.

**AST:**

```go
&IknowIdoBlock{
    Position: Position{Line, Column},
    Body:     *Block,
}
```

**Errors:** `0640`.

### 8.20. Rule of Call Expression as Statement

**Detection:** `TOKEN_IDENT` followed by `TOKEN_LPAREN`, or `TOKEN_IDENT` `.` `TOKEN_IDENT` `TOKEN_LPAREN`.

**Tokens consumed:** as in §7.8.

**AST:** `*CallExpr`.

### 8.21. Rule of Expression Statement

Only the following expression categories are accepted as bare statements:

| Category | Accepted? |
|----------|-----------|
| `TOKEN_STRING` | Yes |
| `TOKEN_NUMBER` | Yes |
| `TOKEN_LPAREN` (parenthesized) | Yes |
| `TOKEN_LPAREN` (array `(...)`) | Yes |
| `TOKEN_LBRACKET` (array `[...]`) | **No** |
| `TOKEN_LBRACE` (dict) | **No** |
| `TOKEN_CHARLIT` | **No** |
| `TOKEN_UNICODE_LIT` | **No** |
| `null`, `true`, `false` | **No** |
| `Promise[...]` | Yes (§8.16) |
| `await expr` | Yes (§8.17) |
| Bare identifier without `;` | **No** |
| Bare identifier with `;` | Yes (§8.4.4) |
| `x.field` alone | **No** |
| `x[index]` alone | **No** |
| `x++`, `x--` | Yes |
| `x = ...` | Yes |
| `foo()` | Yes |

A category marked "No" produces a parser error (`0598: Expected statement`).

### 8.22. Rule of Error Declaration Inside a Function

**Detection:** `TOKEN_KEYWORD("const")` followed by a **non-type-keyword** `TOKEN_IDENT`.

**Tokens consumed:** as in §4.1.

**AST:** `*ErrorDecl`, appended to the enclosing `Block.Statements`.

**Rules:**
- The local `ErrorDecl` is **not** added to `Program.ErrorDecls`.
- The name must begin with an uppercase letter (`0581`).
- If `const` is followed by a type keyword, the construct is a **constant variable** (§8.3), not an error declaration.

**Dispatch table:**

| Next after `const` | Construct |
|--------------------|-----------|
| Type keyword | `const-var-decl` |
| `TOKEN_IDENT` (not a type keyword) | local error declaration |
| `TOKEN_KEYWORD("Error")` | not allowed as a name |

## 9. Operator Precedence

### 9.1. Rule of Precedence Table

The parser uses a Pratt parser (`parseBinary(prec)`) with the following levels:

| Level | Tokens | Operator | Associativity |
|-------|--------|----------|---------------|
| 6 | `TOKEN_DOTDOT` | `..` | Left |
| 5 | `TOKEN_POW` | `**` | Right |
| 4 | `TOKEN_STAR`, `TOKEN_SLASH`, `TOKEN_PERCENT` | `* / %` | Left |
| 3 | `TOKEN_PLUS`, `TOKEN_MINUS` | `+ -` | Left |
| 2 | `TOKEN_LT`, `TOKEN_GT`, `TOKEN_EQUALS`, `TOKEN_NEQ`, `TOKEN_EQEQ`, `TOKEN_LTE`, `TOKEN_GTE` | `< > = != == <= >=` | Left |
| 1 | `TOKEN_AND` | `&&` | Left |
| 0 | `TOKEN_OR` | `\|\|` | Left |

Ternary (`?:`) is at level **-1** (parsed by `parseExpression` after `parseBinary(0)`).

### 9.2. Rule of Precedence Consequences

| Source | Parsed as |
|--------|-----------|
| `1 .. 2 + 3` | `(1 .. 2) + 3` |
| `1 + 2 .. 3` | `1 + (2 .. 3)` |
| `2 ** 3 .. 4` | `2 ** (3 .. 4)` |
| `1 .. 2 .. 3` | `(1 .. 2) .. 3` |

### 9.3. Rule of Parenthesized Override

`(` … `)` overrides default precedence (via §7.2.5).

### 9.4. Rule of Right-Associativity of `**`

`2 ** 3 ** 4` is `2 ** (3 ** 4)`.

The parser achieves this by calling `parseBinary(5)` (same precedence) for the right operand of `**`.

### 9.5. Rule of `=` at Comparison Level

`TOKEN_EQUALS` is in the comparison level. In expression context, `a = b` produces `*BinaryExpr{Op: "="}`.

In statement context, `a = b` is an assignment (§8.4.1).

### 9.6. Rule of Compound Assignment

`+=`, `-=`, `*=`, `/=`, `%=`, `**=` are **statement-level only** (§8.4.1). They are not binary operators.

### 9.7. Rule of Minus and Number Literals

`-` immediately followed by a digit is a number literal (`SNAR-A2 §6.1.2`).

`a - 5` is `a` followed by `-5` (two tokens, no subtraction).

To mean subtraction, write `a - b` or `a - (5)`.

## 10. Grammar

### 10.1. Rule of EBNF

```ebnf
program         = { import } , { error-decl } , { top-level } ;
top-level       = function | includeC-decl ;

import          = "use" , [ "#" ] , import-path ,
                  [ "&" , identifier ] , [ ";" ] ;
import-path     = library-path | module-path ;
library-path    = "lib:" , identifier , "/" , identifier ,
                  { "-" , identifier } ,
                  [ "@" , version-digits ] ;
module-path     = identifier , { "/" , identifier } ;
version-digits  = digit , { digit } , { "." , digit , { digit } } ;

error-decl      = "const" , uppercase-identifier , "{" ,
                  [ error-fields ] , "}" , "=" ,
                  [ "new" ] , error-parent ;
error-fields    = error-field , { "," , error-field } ;
error-field     = identifier , ":" , type ,
                  [ "[" , expression , "]" ] ;
error-parent    = identifier | "Error" ;

function        = [ "async" ] , type , [ "*" ] ,
                  identifier , "(" , [ param-list ] , ")" , block ;
param-list      = param , { "," , param } ;
param           = type , identifier , [ "=" , expression ]
                | "..." , identifier ;

type            = simple-type | array-type | union-type ;
simple-type     = "void" | "int" | "string" | "float"
                | "double" | "bool" | "char" | "dict" | "any" ;
array-type      = "arr" , [ "[" , type , "]" ] ;
union-type      = "T" , "<" , type , { "," , type } , ">" ;

block           = "{" , { statement } , "}" ;

statement       = var-decl
                | const-var-decl
                | error-decl
                | if-stmt
                | case-stmt
                | while-stmt
                | do-while-stmt
                | for-stmt
                | break-stmt
                | continue-stmt
                | return-stmt
                | try-stmt
                | throw-stmt
                | promise-stmt
                | await-stmt
                | includeC-decl
                | iknowido-block
                | assign-stmt
                | postfix-stmt
                | call-stmt
                | expression-stmt ;

var-decl        = type , identifier , [ "=" , expression ] , [ ";" ] ;
const-var-decl  = "const" , type , identifier , "=" , expression , [ ";" ] ;

if-stmt         = "if" , "(" , expression , ")" , block ,
                  { "elsif" , "(" , expression , ")" , block } ,
                  [ "else" , block ] ;

case-stmt       = "case" , "(" , expression , ")" , "{" ,
                  case-body , "}" ;
case-body       = case-branch , { case-branch } , [ default-branch ]
                | default-branch ;
case-branch     = ( expression
                  | "(" , expression , { "," , expression } , ")" )
                , block , "," ;
default-branch  = "_" , block , "," ;

while-stmt      = "while" , "(" , expression , ")" , block ;
do-while-stmt   = "do" , block , "while" ,
                  "(" , expression , ")" , [ ";" ] ;
for-stmt        = "for" , "(" , type , identifier ,
                  "in" , expression , ")" , block ;

break-stmt      = "break" , [ ";" ] ;
continue-stmt   = "continue" , [ ";" ] ;
return-stmt     = "return" , [ expression ] , [ ";" ] ;

try-stmt        = "try" , block , catch-clause , { catch-clause } ;
catch-clause    = "catch" ,
                  [ "(" , error-type-name ,
                    [ "as" , identifier ] , ")" ] ,
                  block ;
error-type-name = identifier , { "." , identifier } ;

throw-stmt      = "throw" , expression , [ ";" ] ;
promise-stmt    = "Promise" , "[" , expression , "]" , [ ";" ] ;
await-stmt      = "await" , unary-expr , [ ";" ] ;
includeC-decl   = "includeC" , tilde-block ;
iknowido-block  = "IknowIdo" , block ;

assign-stmt     = assign-target , assign-op , expression , [ ";" ] ;
assign-target   = identifier
                | identifier , "[" , expression , "]" ;
assign-op       = "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "**=" ;

postfix-stmt    = identifier , ( "++" | "--" ) , [ ";" ] ;
call-stmt       = call-expr , [ ";" ] ;
expression-stmt = expression , [ ";" ] ;

expression      = ternary-expr ;
ternary-expr    = binary-expr , [ "?" , expression , ":" , expression ] ;
binary-expr     = unary-expr , { binary-op , unary-expr } ;
binary-op       = "\|\|"
                | "&&"
                | comparison-op
                | additive-op
                | multiplicative-op
                | power-op
                | range-op ;
comparison-op   = "==" | "!=" | "<" | "<=" | ">" | ">=" | "=" ;
additive-op     = "+" | "-" ;
multiplicative-op = "*" | "/" | "%" ;
power-op        = "**" ;
range-op        = ".." ;

unary-expr      = unary-op , unary-expr | postfix-expr ;
unary-op        = "!" | "-" | "$" | "await" ;

postfix-expr    = primary-expr , { postfix-op } ;
postfix-op      = "." , identifier , [ "(" , [ arg-list ] , ")" ]
                | "." , "length"
                | "[" , expression , "]"
                | "++"
                | "--"
                | "^" , format-spec ;

format-spec     = precision-format | trim-format ;
precision-format = number-with-f-suffix ;
trim-format     = "X" , ( digit , { digit }
                        | "{" , digit , { "," , digit } , "}" ) ;

primary-expr    = number-literal
                | string-literal
                | char-literal
                | unicode-literal
                | "null"
                | "true"
                | "false"
                | identifier
                | call-expr
                | error-instance
                | dict-literal
                | "[" , [ expression , { "," , expression } ] , "]"
                | "(" , expression , ")"
                | "(" , expression , "," , expression ,
                  { "," , expression } , ")"
                | "Promise" , "[" , expression , "]"
                | "type" , "(" , expression , ")" ;

error-instance  = ( identifier | "Error" ) , "{" ,
                  [ error-field-init ,
                    { "," , error-field-init } ] , "}" ;
error-field-init = identifier , ":" , expression ;

dict-literal    = "{" , [ dict-entry , { "," , dict-entry } ] , "}" ;
dict-entry      = identifier , ":" , expression ;

call-expr       = ( identifier | module-call ) ,
                  "(" , [ arg-list ] , ")" ;
module-call     = identifier , "." , identifier ;
arg-list        = expression , { "," , expression } ;

uppercase-identifier = "A".."Z" , { letter | digit | "_" } ;
identifier      = ( letter | "_" ) , { letter | digit | "_" } ;
letter          = "A".."Z" | "a".."z" ;
digit           = "0".."9" ;
```

### 10.2. Rule of Grammar Priority

Where the EBNF and the textual rules disagree, the **textual rules take priority**.

## 11. Conformance

### 11.1. Rule of Conformance

A `*.sk` file conforms if and only if all rules of Sections 1–10 are satisfied.

### 11.2. Rule of Non-Conformance

A file violating at least one rule does not conform.

### 11.3. Rule of Violation

A record violating any rule is **invalid**.

## 12. Examples

### 12.1. Valid Examples

**Imports:**
- `use std/strings`
- `use #std/strings`
- `use std/strings &str`
- `use lib:alice/math@1.0.0`
- `use #lib:bob/my-utils &utils`

**Types:**
- `int`, `string`, `void`, `bool`, `char`, `any`, `dict`
- `arr`, `arr[int]`, `arr[arr[string]]`
- `T<int, string>`, `T<int, float, bool>`, `T<int>` (normalizes to `int`)

**Functions:**
- `int foo(int x) { return x }`
- `void bar() { }`
- `async int fetch(string url) { return 0 }`
- `int* privateFunc(int x) { return x }`
- `int add(int x, int y = 0) { return x + y }`
- `int sum(...args) { return 0 }`
- `int sum(int a, int b, ...rest) { return a + b }`

**Statements:**
- `int x = 5`
- `int y`
- `const int z = 10`
- `x = 5`
- `x += 5`
- `x++`
- `arr[0] = 10`
- `if (x > 0) { return 1 } elsif (x < 0) { return -1 } else { return 0 }`
- `while (x > 0) { x -= 1 }`
- `do { x -= 1 } while (x > 0)`
- `for (int i in 0..10) { print(i) }`
- `case (x) { 1 { } , _ { } , }`
- `break`, `continue`, `return x`
- `try { } catch (MyError as e) { }`
- `try { } catch { }`
- `throw MyError{code: 1}`
- `Promise[42]`
- `await foo()`
- `includeC ~~~int x = 5;~~~`
- `IknowIdo { return 0 }`

**Expressions:**
- `1 + 2 * 3`
- `a && b || c`
- `x ? 1 : 0`
- `0..10`
- `a.length`, `arr[0]`, `obj.field`, `foo()`, `mod.func()`
- `[1, 2, 3]`, `[]`, `(1, 2, 3)`
- `{key: 1, other: 2}`
- `Foo{code: 1, message: "error"}`
- `type(x)`, `Promise[42]`, `1..4.sum()`
- `x^3f`, `x^X9`, `x^X{1,8}`

### 12.2. Invalid Examples

**Control flow (parentheses):**
- `if x > 0 { }`
- `elsif x > 0 { }`
- `while x > 0 { }`
- `do { } while x > 0`
- `case x { 1 { } , }`
- `for int i in 0..10 { }`
- `if (a) && (b) { }`

**Types:** `arr[]`, `arr[void]`, `T`, `T<T<int, string>, float>`, `dict[int]`

**Functions:**
- `void foo(int x, int x)`
- `void foo(...args, int x)`
- `async void foo()`
- `foo()`
- `func foo()`

**Error declarations:** `const foo{...}`, `const Foo{...} = Bar` (undeclared `Bar`)

**Statements:**
- `case (x) { }`
- `case (x) { 1 { } }`
- `try { }`
- `throw`
- `if`
- `while`
- `for (i in 0..10)`
- `for (int i 0..10)`
- `do { }`
- `obj.field = 5`
- `x[0]` alone
- `x.field` alone
- `[1, 2, 3]` alone
- `{key: 1}` alone
- `'a'` alone

**Assignments:** `1 = 5`, `(a) = 5`, `a.b.c = 5`

**Expressions:**
- `foo()[0]`, `foo().length`, `foo().field`, `(a + b).field`
- `5++`
- `^3`, `^21f`, `^X{}`, `^X{1,a}`
- `()`
- `[1, 2, ]`
- `{x: 1, x: 2}`
- `Foo{x: 1, x: 2}`
- `&name`

## 13. Design Notes

### 13.1. Rule of Range Precedence

`..` has the highest precedence among binary operators (§9.1). This is **intentional** and **normative**.

### 13.2. Rule of Optional Semicolons

Semicolons are never required between statements.

### 13.3. Rule of No Nested Comments

Comments do not nest (SNAR-A2 §3.3).

### 13.4. Rule of Two Array Forms

Both `[...]` and `(a, b, c)` are array literals. `(a)` is a parenthesized expression.

### 13.5. Rule of Minus Ambiguity

See §9.7.

### 13.6. Rule of `T` Keyword

`T` is reserved for union types. A variable named `T` cannot be declared.

### 13.7. Rule of No `&` References

Skorpion has no `&name` references in expressions (unlike SPC). `&` is valid only in import aliases.

### 13.8. Rule of `#` / `&` No-Ops

Both are syntactically accepted but semantically inert.

### 13.9. Rule of Mandatory Parentheses

All control-flow conditions (`if`, `elsif`, `while`, `do-while`, `case`) and the `for-in` header require parentheses.

`catch` parentheses remain optional (§8.14.1).

## 14. Known Limitations of the Reference Implementation

### 14.1. Top-Level Garbage

The parser silently skips unknown top-level tokens. A conforming compiler **may** reject them.

### 14.2. `void` Variable Type Not Rejected

`void x = 5` parses. SNAR-A4 should reject it.

### 14.3. Field Assignment Unreachable

`name.field = value` is rejected (`0511`). Use `y = name.field` on the RHS.

### 14.4. Expression Statement Subset

See §8.21.

### 14.5. `x` Without Semicolon

`x` alone is a parser error.

### 14.6. `arr[]` Rejected

Error `0561`.

### 14.7. `T` Without `<` Rejected

Error `0608`.

### 14.8. `const` Disambiguation

See §8.22.

### 14.9. `_` Is an Identifier

`_` in `case` default is `TOKEN_IDENT`.

### 14.10. `#` No-Op

See §3.1.1.

### 14.11. `&` No-Op

See §3.1.2.

### 14.12. `x[index]` Alone

Parser error `0516`.

### 14.13. Parentheses Around Conditions

Mandatory since this standard.

### 14.14. `catch` Parentheses Optional

See §8.14.1.
